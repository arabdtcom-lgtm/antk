### Objective 2: `server.ts` Stateless Context & Route Security
- **Status**: 🔴 **FAIL (Critical Vulnerabilities Found)**
- **Findings**:
  1. **Stateless Request Context**: ✅ **PASS**. `getUserFromReq` extracts user identity dynamically per-request from `x-user-email`, `x-user-id`, or `Authorization: Bearer <token>` headers without storing user state in module-level global variables.
  2. **Support Tickets Security Bug**: 🔴 **FAIL**.
     - `POST /api/support/tickets/:id/reply` (line 527) is missing `requireAdmin` or `requireAuth` middleware. Unauthenticated public clients can send POST requests to reply to any customer support ticket.
     - `GET /api/support/tickets` (line 494) is completely unauthenticated and unpartitioned, returning all support tickets of all users to any public requester.
  3. **Unauthorized Profile Balance Escalation**: 🔴 **FAIL**.
     - `PUT /api/auth/profile` (lines 133-146) accepts `{ balance: number }` in `req.body` and directly updates the user's account balance in `DB.users` without admin authentication or payment verification.
  4. **Shipment Tracking Hijacking**: 🔴 **FAIL**.
     - `POST /api/shipments/update-tracking` (lines 299-318) has **no authentication or seller/admin check**. Any unauthenticated caller can overwrite carrier and tracking numbers for any auction shipment.
  5. **Unprotected CRM AI Endpoints**: ⚠️ **WARNING / DEFECT**.
     - Gemini AI endpoints (`/api/crm/ai-chat`, `/api/crm/analyze-image`, `/api/crm/transcribe-audio`, `/api/crm/ai-campaign`) lack authentication or admin checks, exposing server-side Gemini API quota to unauthenticated public abuse.

### Objective 3: `firestore.rules` Restriction Check
- **Status**: 🔴 **FAIL (Broken & Inconsistent Rules)**
- **Findings**:
  1. **`/auctions/{auctionId}` Rules Flaw**:
     - Rule uses `isOwner(resource.data.sellerEmail)`. However, auction documents generated by `server.ts` and `src/utils/firebase.ts` store `seller` as an object `{ name, rating }` and do **not** write a top-level `sellerEmail` field. `isOwner(resource.data.sellerEmail)` evaluates to `false` for genuine sellers.
     - `allow update` permits any authenticated user to modify `['currentPrice', 'bidsCount', 'highBidder', 'highBidderName', 'viewsCount']` directly on Firestore without backend bid validation or minimum increment enforcement.
     - Frontend `checkoutEscrowInFirestore` attempts to update `trackingNumber` and `status` on `/auctions/{auctionId}`, which is rejected by rules for non-admin buyers.
  2. **`/shipments/{shipmentId}` Rules Flaw**:
     - Rule `allow create, update: if isAdmin() || (isSignedIn() && isOwner(request.resource.data.buyerEmail))` allows any **buyer** to update shipment status (e.g. marking shipment as `delivered` or altering delivery history).
     - Sellers are not permitted to read or update shipment records for items they sold because `allow read` only checks `isOwner(resource.data.buyerEmail)`.
  3. **`/autobids/{autobidId}` Rules Flaw**:
     - Rule `allow read, write: if isSignedIn() && (isOwner(resource.data.userEmail) || ...)` evaluates `resource.data.userEmail` on document `create` when `resource` is `null`, causing Firestore Security Rules execution errors.

## Required Remediations Before Re-Audit

1. **Fix `server.ts` Security**:
   - Add `requireAdmin` to `POST /api/support/tickets/:id/reply`.
   - Restrict `GET /api/support/tickets` to return user's own tickets unless caller is admin.
   - Remove `balance` mutation capability from `PUT /api/auth/profile`.
   - Add `requireAuth` and seller/admin validation to `POST /api/shipments/update-tracking`.
   - Add `requireAuth` / `requireAdmin` to CRM AI endpoints.

2. **Fix `firestore.rules` Security Rules**:
   - Add `sellerEmail` to auction schema/documents or update rule to check `resource.data.seller.email`.
   - Restrict `/shipments/{shipmentId}` updates to seller/admin, and allow read for both buyer and seller (`isOwner(resource.data.buyerEmail) || isOwner(resource.data.sellerEmail) || isAdmin()`).
   - Fix `/autobids` rule condition to check `resource == null || isOwner(resource.data.userEmail)`.
